# Sistema de Gestión de Pedidos y Ventas

## 1. Descripción del sistema

El Sistema de Gestión de Pedidos y Ventas es un proyecto de software orientado a organizar la información de clientes, productos, pedidos y ventas de un negocio.

## 2. Objetivo

Diseñar un sistema que facilite la organización y el seguimiento de los procesos de pedidos y ventas, contribuyendo a mejorar el control de la información comercial.

## 3. Problema que busca resolver

El manejo manual o desorganizado de la información puede dificultar el seguimiento de los pedidos, el control de los productos y la consulta de las ventas. El proyecto busca ofrecer una solución digital que permita organizar estos procesos.

## 4. Funcionalidades principales

- Gestión de clientes.
- Gestión de productos.
- Registro y seguimiento de pedidos.
- Registro de ventas.
- Consulta y generación de reportes.
- Control de acceso de usuarios, previsto dentro del alcance del sistema.

Estas funcionalidades corresponden al alcance previsto y no implican que todas estén implementadas actualmente.

## 5. Arquitectura propuesta

Se propone una arquitectura cliente-servidor, separando la interfaz de usuario, la lógica de negocio y el acceso a los datos. La implementación definitiva deberá documentarse conforme se desarrollen y validen los componentes técnicos.

## 6. Organización frontend y backend

### Frontend

El frontend será la parte visual con la que interactuará el usuario. Permitirá mostrar formularios, pantallas y opciones para gestionar clientes, productos, pedidos y ventas, además de presentar los resultados de las operaciones.

### Backend

El backend procesará las solicitudes recibidas, aplicará las reglas de negocio, validará los datos y coordinará las operaciones con la base de datos.

### Comunicación

Se propone que el frontend y el backend se comuniquen mediante solicitudes HTTP a través de una API. El backend devolverá las respuestas correspondientes a cada operación. Esta comunicación queda pendiente de implementación y verificación técnica.

## 7. Herramientas utilizadas y previstas

- Git y GitHub para el control de versiones y el alojamiento del repositorio.
- GitHub Issues para registrar incidencias y tareas pendientes.
- GitHub Projects para organizar el seguimiento del trabajo.
- Markdown para la documentación.
- Diagramas UML para representar el diseño del sistema.

## 8. Control de versiones

Los cambios relevantes se registrarán mediante confirmaciones (commits) en Git. Cada confirmación deberá incluir un mensaje que describa el cambio realizado. Las incidencias y tareas pendientes se organizarán mediante GitHub Issues y se vincularán al tablero de seguimiento cuando corresponda.

## 9. Estado actual del proyecto

El proyecto se encuentra en una etapa de organización y documentación técnica. Es necesario incorporar y verificar los documentos de requisitos, los modelos UML, la arquitectura y las evidencias de avance.

La implementación de las funcionalidades y las pruebas deberán documentarse cuando existan evidencias verificables de su realización.
